# Comparison verification — 0.11.0

The Gallery selects two still images in order with Ctrl/Command-click and opens the shared comparison component. A stays on the left until the arrow latches B; holding Space temporarily overlays an independent B element on the left. The right element is retained. Neither entering comparison nor switching reads captions or changes the saved Caption preference. Escape returns to the virtual grid with selection and scroll intact.

The Webview and browser share `media/compareView.js` and `compareView.css`. Zoom is relative to each pane's fitted size; normalized centers link corresponding regions across different image sizes and orientations. Panning, independent views and double-click fitting are tested. Switching image sources does not change either camera. Browser handoff includes both known IDs, preview resolution, original-mode flags, linked state, cameras and the latched display state. Private token sessions use the existing SSH forward; no source path supplied by a client can open an unknown image. Browser state storage is scoped to each session.

Both previews load as foreground tasks. A, B and B's left-hand copy remain protected in the decoded-image cache, and ordinary neighbour preloading stops. The extra copy counts toward the seven-image / 128 MiB estimate. Active originals/animations can exceed that estimate; unrelated history is removed first, and normal eviction resumes on exit. Cached sources are validated at entry, focus and every 15 visible seconds. Configuration changes, file versions and request tokens invalidate stale loads; retries and explicit original mode are per side. Ready A/B changes only update visibility and transforms.

The complete 171-test suite passes on Node 25.9 and the minimum Node 18.18.2. Node 25 runs with two test files at a time; Node 18's runner lacks that option, so every test file was run sequentially. This avoids unrelated FFmpeg/process-startup timing tests competing with browser benchmarks. Coverage includes selection order, macOS Ctrl pointer/context-menu events, virtual-grid recycling, search/refresh, Space repeat/release/blur/hiding, linked and independent pan/zoom, right-element identity, memory pressure, stale results, per-side retry/original, private handoff and failed opening, RAW/EXIF, transparency, animation, video timestamp and special-filename regressions.

`test/compareBrowserSmoke.cjs` runs the actual generated Webview HTML through its host message bridge and opens the real browser session in Chrome, using synthetic 3200 × 1800 and 1800 × 3200 PNGs. It checks native fullscreen, state inheritance, independent views, drag, two-second control hiding and 460-pixel side-by-side layout. In one local 60-switch sample per view, P95 switch-to-two-animation-frames was about 34 ms; switches produced zero additional image requests, image decodes or Caption messages. This is a warm, already-decoded synthetic sample, not a cold-load or remote-network guarantee. The HTML bridge is not a substitute for a manual end-to-end VS Code UI test after the user reloads the installed extension.

Run the smoke with `GALLERY_PLAYWRIGHT_MODULE=/path/to/playwright node test/compareBrowserSmoke.cjs`. Run `GALLERY_COMPARISON_RUNTIME=/installed/extension/dist node test/verifyComparisonHost.cjs /source/folder` **on the source host** for a bounded two-image cold/warm preview check. It serves and consumes preview bytes on that host, reports only dimensions/byte counts/timings, verifies zero Caption reads and unchanged source metadata, revokes the session and removes its temporary previews. It never exports original media.

The final VSIX is checked against every compiled/runtime file in `dist` and `media`, including the comparison scripts, Worker/process entry points, WASM32 runtime, bundled HLS.js and licenses. Packaging and installation are separate from Marketplace publication; the 0.11.0 task does not publish or reload user windows.
