# 0.11.5 视频缓冲排查

2026-11-14，在 SSH Home 对用户提供的视频原地测量，未修改或下载原始媒体。源文件名和完整路径不写入公开记录。

源文件为 MKV、VP9、3840×2160、约 59.95 fps，AAC 音轨、−90° 旋转，时长 113.685 秒；不是截图中显示 3:15 的同一时长。关键帧约每 6.006 秒一帧。服务器为 96 逻辑核，初始 load 约 4.7，FFprobe 元数据读取 88 ms。

| --- | ---: | ---: |
| 0–4 秒 | 5.671 秒 | 4.627 秒 |
| 4–8 秒 | 7.852 秒 | 6.090 秒 |

原链路串行准备八秒媒体耗时 13.523 秒。候选参数两任务并行时，0/4 秒两片共 6.302 秒，8/12 秒两片共 7.124 秒。VP8 输出约 2.1 MB／四秒（4.3 Mbps）。相同输入增加输出编码线程到四、八未改善单片耗时。解码、旋转、缩放本身已有显著成本；输出设置为 1080p 不会免去 4K 输入解码。

这些是少量、服务器端实源样本，包含当时源文件读取与转码，不包含 SSH 私有转发和客户端播放。不能据此保证 P95、任意倍速或持续播放无卡顿。完整交互验收的浏览器工具连接超时，本次没有宣称端到端通过。

修复保留两个主机任务槽位，客户端同时最多取两片，并串行追加；目标约 20 秒观看缓冲、最多 48 秒媒体，内存预算不足即停止向前追加。暂停只取当前片，拖动优先新当前位置并取消多余工作。输出仍为 30 fps，画质和方向规则保留，未启用 GPU 或整段预转码。HLS 浏览器按观察到的片段大小收紧提前缓冲。

分片响应新增 Server-Timing 的 prepare、queue、encode、cache；客户端记录完整请求和剩余缓冲时间。prepare 是包含排队／编码／缓存的主机准备总时间，不能把各项再次相加。请求总耗时减去 prepare 只近似表示传输、转发等剩余开销。
